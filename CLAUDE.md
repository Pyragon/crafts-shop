# MaBrown's Creations

An arts-and-crafts storefront for a small-batch maker in Canada. Catalogue with
variants and personalisation, cart, accounts, Stripe checkout, and an admin
still to come.

**It is live but gated** at https://mabrowns.ca — every visitor sees a
coming-soon page unless allowed. Nothing here has taken real money yet.

## Stack

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind v4 · Prisma 7 +
SQLite · Stripe · Resend.

**Pinned on purpose:**

- **Prisma 7.10.0.** npm's `latest` tag points at an `8.0.0-rc`. An unpinned
  install silently mixes an RC CLI with a stable client. Check
  `npm view prisma dist-tags` before touching it.
- **No Auth.js.** v5 is still beta and v4 predates the App Router. Sessions are
  hand-rolled; passwords use `scrypt` from Node's standard library, so there is
  no native dependency to compile.

## Running it

```sh
npm run dev:origin   # Next on 127.0.0.1:3000 (loopback only)
npm run proxy        # Caddy on :80 and :443
```

```
Internet → Cloudflare → Caddy (:80, :443) → Next.js (127.0.0.1:3000)
```

Caddy terminates TLS with Cloudflare Origin CA certs; Cloudflare is on **Full
(strict)**. `caddy reload --config deploy/Caddyfile` applies changes without
dropping connections.

To see the site as a customer would, the gate needs unlocking — visit
`/?preview=<SITE_PREVIEW_TOKEN>` once (the token is in `.env.local`).

## Environment quirks

- **Node lives in `~/.local/lib/node`** — installed without sudo, already on
  `PATH` via `.bashrc`.
- **No passwordless sudo.** Anything needing root has to be handed to Cody.
- **Ports below 1024 are bindable** because
  `net.ipv4.ip_unprivileged_port_start=80` was set.
- **The repo sits on an NTFS partition.** SQLite WAL needs mmap-backed shared
  memory that `ntfs3` does not provide, so the dev database lives on ext4 at
  `~/.local/share/mabrowns-creations/dev.db`. Don't move it back.

## Gotchas that have already cost time

Each of these produced a confusing symptom and a wrong first diagnosis.

1. **Dev asset caching.** Next's dev CSS/JS chunks keep a *stable URL* while
   their contents change. Any cache serving by URL hands back stale styles, and
   the symptom is a component rendering as if a newly-added utility class does
   not exist. Caddy now sends `no-store` for `/_next/*`. If something looks
   wrong after a change, **hard-refresh before debugging anything else.**
2. **Restart the dev server after a schema change.** The Prisma client is
   cached on `globalThis` to survive HMR, so a regenerated client is not picked
   up by a running process. The symptom is misleading:
   `Cannot read properties of undefined (reading 'create')`.
3. **`prisma format` silently breaks string-replacement edits.** It realigns
   whitespace, so a scripted edit matching on spacing misses and reports
   success. This has bitten twice. Edit the schema by locating the model and
   field **by line**, then grep to confirm the field is present before
   migrating.
4. **Route types are generated by `next dev`/`next build`.** A new page fails
   typecheck with *"does not satisfy the constraint 'AppRoutes'"* until the
   route has been compiled once.
5. **Resend rejects `example.com` addresses.** Test emails need a real domain —
   `admin@mabrowns.ca` works and lands in Cody's Gmail.
6. **`server-only` cannot be imported outside Next.** Testing a module that
   imports it via `tsx` fails; strip that line into a copy instead.

## Conventions

- **Money is integer cents.** Never floats. Display with `formatPrice()`.
- **Storefront reads go through `@/lib/catalog`**, which applies the
  `PUBLISHED` filter in one place. Never query products straight from a page.
  The seed keeps one product permanently in `DRAFT` as a standing check.
- **Never import `@/lib/db` from a client component.** It pulls
  `better-sqlite3` into the browser bundle. `db.ts` imports `server-only` so
  this fails loudly. Shared pure helpers get their own module — see
  `swatch.ts`, `variants.ts`, `shipping.ts`.
- **Every product has at least one variant**, even with no options. Stock,
  price overrides and SKUs live on the variant, and the cart always references
  a variant id — so there is never a "does this have variants?" branch.
- **Variants vs personalisation.** A variant is a fixed choice the shop decides
  in advance (glaze, size, design). Personalisation is free text only the
  customer can supply (a monogram). Variants carry price; personalisation never
  does.
- **The cart and checkout are server-authoritative.** The client sends ids and
  desired quantities; the server recomputes every cent against live stock and
  live prices, and clamps rather than trusting.
- **Orders snapshot what was bought.** Names, prices, variant labels and
  personalisation are copied, not referenced, so editing the catalogue cannot
  rewrite what someone paid for.
- **Payment and fulfilment are separate fields.** An order can be refunded
  after shipping, or paid and not yet started.

## What is real and what is placeholder

Be careful not to present invented data as researched — this has already
happened once.

| Real | Placeholder |
|---|---|
| Domain, TLS, email sending and receiving | **All product names, descriptions, prices** |
| Stripe sandbox integration | **All shipping rates** — invented, not Canada Post |
| The schema and all flows | Product images (deterministic gradients) |
| | Blog posts (`src/lib/placeholder-data.ts`) |
| | Tagline and studio description |

Shipping rates and sales tax are both **unresolved and on the launch
checklist**. Rates are marked as placeholders in `shipping.ts`; tax returns 0
and the checkout says so.

## Working style Cody expects

- **Verify rather than assert.** Claims about behaviour should come from having
  run it. Several real bugs here were found by checking an outcome that "should"
  have been fine — a cart that stayed full after payment, a canonical URL
  pointing at localhost.
- **Say when something is invented.** Placeholder data presented confidently is
  worse than an obvious gap.
- **Correct the record when wrong.** Two diagnoses in this project were wrong
  and had to be retracted; the corrections are in the git history and comments
  on purpose.
- Commit and push as work completes, with messages that explain *why*.
- Test on a real device where it matters — Cody is on Brave/Android, and a
  headless pass has already disagreed with what he could see.
